# Blender3D product modeling

Models in this repo are generated by Python scripts run in headless Blender, never built by hand, so they can be rebuilt and their dimensions verified. The reference implementation is `scripts/build_glosola_hss1751_6pk.py`. Copy its structure for new products.

## Environment

- Blender: `/Applications/Blender.app/Contents/MacOS/Blender` (4.2.1 LTS). It is not on `PATH`.
- Run a build script: `"$BLENDER" -b --factory-startup -P scripts/<build_script>.py`
- Run a script against an existing file: `"$BLENDER" -b <file.blend> --factory-startup -P <script>.py -- <args>`. Script arguments go after `--` and are read from `sys.argv`.

## Workflow

1. **Look at the product photos before modeling anything.** Spec text alone is misleading. The first Glosola model was built from text fields only and came out as a thin pole with a head on top, when the real product is a single straight cylinder.
   - Amazon product pages are very large (about 1.3M characters), and fetching the page with `curl` was blocked. Use WebFetch with `offset`, running calls in parallel.
   - The gallery's `colorImages` data, with `hiRes` URLs, was around offset 200000.
   - Downloading those images with `curl` from `m.media-amazon.com` does work. Request `https://m.media-amazon.com/images/I/<id>._AC_SL1000_.jpg` and save them to their own directory under `/tmp`. View them with Read.
   - Look for a **"Product Detail & Size"** diagram (usually the last gallery image). It shows the true shape, the labeled dimensions, and the exploded parts.
   - Customer review photos show hidden parts, such as how the stake attaches. Review sections didn't appear in the fetched page text, so ask the user for the image URL. Photos of broken parts can mislead: in RReig's Glosola photo, the "separate" small ring is actually the plug's snapped-off socket. Confirm how the parts go together with the user before modeling them.
2. **Get the dimensions.**
   - The **"Measurements"** expander (Item Dimensions, Size, Weight) was around offset 800000–900000.
   - The "About this item" bullets were around offset 1200000–1300000.
   - The fields disagree with each other. Glosola's "Item Dimensions" says 3.5" × 17.3" × 3.5" (labeled L × W × H, but 17.3" is the height), while the "Size" field and the diagram both say 3.15" wide. Prefer the diagram plus the "Size" field. Tell the user about any conflict and make the value a single constant so it's easy to switch.
3. **Measure part proportions from the size diagram.** Check that the scale is the same both ways (labeled width ÷ px width ≈ labeled height ÷ px height), then measure each part's pixel span. Use Blender's bundled numpy (see below).
4. **Write `scripts/build_<product_slug>.py`.** Use the conventions below. Put the listing values (in inches × 2.54) and the measured heights in named constants at the top. The docstring should state the sources and which values are estimates.
5. **Build and verify.** The script must print each object's dimensions in mm, and they must match the listing to 0.01 mm. If they don't, fix the geometry; don't round the reported numbers.
6. **Render previews and compare them against the product photos** using `${CLAUDE_SKILL_DIR}/scripts/render_preview.py` (see below). For multi-part models, also run `render_fit_check.py`. Open the PNGs with Read before reporting back.
7. **Update `README.md`.** Add the model's dimension sources, the part height table, which values are estimates, and its rebuild command.

## Measuring a diagram image

Run this with `"$BLENDER" -b --factory-startup -P measure.py -- <image.jpg>`. Keep the script outside the image directory.

```python
import bpy, numpy as np, sys
img = bpy.data.images.load(sys.argv[sys.argv.index("--") + 1])
w, h = img.size
lum = np.array(img.pixels[:]).reshape(h, w, 4)[::-1, :, :3].mean(axis=2)  # rows top-down
# For each row y in the drawing's column range: dark pixels (< 0.35) = black parts,
# non-white (< 0.85) = clear/light parts. Print the rows where the span changes to find
# the part boundaries, then convert px to cm with the labeled overall dimension.
```

## Conventions

- **One item per model** unless the user asks for more. A pack name like `.6PK` is just part of the model name; it doesn't mean six objects.
- **Naming:** The user's model name (e.g. `Glosola_HSS1751.6PK`) is used for the main object, its mesh, the collection, and the output file `models/<NAME>.blend`. Separate parts are named `<NAME>_<Part>` (`_Base`, `_Spike`). Materials are prefixed with the brand (`Glosola_ABS_Black`, …).
- **Units:** Metric, displayed in millimeters (the user's preference), true scale:
  ```python
  us = scene.unit_settings
  us.system = "METRIC"; us.scale_length = 1.0; us.length_unit = "MILLIMETERS"
  CM = 0.01  # the build script's constants are written in cm; multiply by CM when creating geometry
  ```
  Report sizes in mm to match the scene. Report to 0.01 mm, which is the same precision as the old 3-decimal cm output. Keep `scale_length = 1.0`. Setting it to `0.01` makes 1 unit equal 1 cm in the UI, but FBX, glTF and STL exports then come out 100× off.
- **Origin** at the bottom center of each object. For a single-mesh item that's the stake tip. In a multi-part model, the body's origin is on the mating plane where the parts join.
- **Fresh scene:** Start with `bpy.ops.wm.read_factory_settings(use_empty=True)` so the script is deterministic.

## Multi-part models

When the user wants parts as separate meshes (e.g. a plug and spike that insert into the body):

- Build each part in its own local coordinates, then parent it to the body with `obj.parent = body` and a local `location` offset, so the default file shows the assembled product.
- To show the parts separately, use one `EXPLODE_GAP` constant (`0` = assembled). `explode_along_z` in the reference script measures the assembled size first, then stacks the parts in assembly order with the gap between bounding boxes. It applies the shifts parents first, so a parent's move doesn't drag its children twice, and it prints the resulting gaps.
- Keep the assembled bounding box equal to the listing dimensions, and print both each part's size and the assembled size (see `world_bounds` in the reference script).
- Never model printed parts line-to-line with what they fit into. FDM prints come out oversize. The Glosola plug's ribs, modeled exactly on the estimated pipe inside diameter, wouldn't go into the real pipe. Give the mating size its own constant (`PIPE_ID`, to be replaced by a caliper reading) and a separate clearance (`RIB_CLEARANCE`). Put flat rib corners on the target radius, so the faces don't poke past it. Then measure the exported file to confirm the clearance.
- Give a hole its own constant (`BORE_D`) and the socket's outside diameter its own constant (`SOCKET_OD`), and size neither from the modeled collar or from each other. Then changing the wall never moves the hole, and the wall is only a result. Always read the hole diameter back from the exported file. A hole derived from a modeled estimate (`COLLAR_D + clearance`) drifted from what test prints needed, and the user stopped caring about the spike's lip once the stake fit.
- Ends of features that blend into a curved wall (rib lead-ins) should finish slightly inside the polygonal wall (0.05 mm), not exactly on the true radius. Otherwise the toolbox flags hair-thin flaps between the polygon's corners as thin faces.
- When the user compares prints ("the Before column"), confirm which print each size belongs to before reusing it. Once, the Before and Now columns were swapped, which sent the sizes the wrong way. Diameters and radii differ by 2×: use whichever the user used, and say which in the table.
- When the mating part can't be measured (the Glosola pipe is slightly out of round), tune sizes only from test prints. Once two prints bracket a fit (one too big, one too loose), set the next size midway between them. Say which sizes are only references, so estimates of the mating part aren't quoted as real gaps.
- Name fits explicitly in constants. The Glosola plug's wedge rib tips sit `RIB_CLEARANCE` under the pipe's inside diameter, and the hole (`BORE_D`) is smaller than the spike's lip. A part that slides inside another needs a hollow outer part, so make the outer one a tube.
- Make each removable part watertight (non-manifold edges = 0) so it can be exported to STL. Solids of revolution: build them with `add_lathe`. Mixed shapes: join them with an EXACT Boolean union baked via `bpy.data.meshes.new_from_object(obj.evaluated_get(depsgraph))`, then delete the temporary objects.
- "Flush" means the part's outside surface lines up with the body's outside surface. For the Glosola plug, that's a flange with the same diameter as the pipe; it doesn't mean "no flange". Ask for a clear photo of the part instead of guessing from a vague description.
- Count repeated features (ribs, pins) from a photo only if the whole part is visible. A side view shows about half the ribs. The Glosola plug has 6 wedge ribs, not the 4 a side photo suggested.

## Geometry pattern

Build the item into a single bmesh, with one material index per part, instead of separate `bpy.ops.mesh.primitive_*` objects. This avoids context problems in background mode and gives one joined mesh with material slots. The reference script has these helpers:

- `add_cylinder(bm, mat_index, z0, z1, r0, r1=None, segments=64)`: a capped cylinder or cone made with `bmesh.ops.create_cone`. The sides are smooth and the n-gon caps flat. It returns the new faces.
- `add_tube(bm, mat_index, z0, z1, outer_r, inner_r, segments)`: a closed hollow tube. `outer_r(angle)` sets the outer profile, for example fluted ribs with `r - depth * sin(N * a / 2) ** 2`. Use it for clear lenses so the parts inside them show.
- `add_lathe(bm, mat_index, profile, segments=64)`: revolves a closed `(r, z)` profile with `bmesh.ops.spin(..., use_merge=True)` into a watertight solid, e.g. a cup with a molded socket.
- `add_cross_loft(bm, mat_index, levels, thickness)`: lofts a "+" cross section through `(z, span)` levels, e.g. a finned stake that tapers to a point.
- `add_wedge_ribs(bm, mat_index, count, r_root, r_surface, r_tip, z0, z1, lead, thickness)`: axial crush ribs on a cylinder wall, with a sloped lead-in at the open end. Their roots sit inside the wall so they can be boolean-unioned onto it.
- `add_radial_ribs(bm, mat_index, count, r0, r1, z0, z1, thickness, offset_deg)`: flat radial support ribs, e.g. from a socket to a cup wall. Start r0 inside the socket wall (not at the bore) so the ribs union with the wall and leave the bore clear. To check the bore, cast rays straight up through it with `BVHTree.ray_cast`; nearest-point inside/outside tests give false hits at edges.
- `union_bmeshes(scene, name, mat, bm_a, bm_b)`: EXACT Boolean union of two bmeshes into one watertight mesh datablock.
- Recessed panels: `bmesh.ops.inset_region(bm, faces=[top], thickness=rim, depth=-recess)` keeps the original face as the inner one, so you can give it a different material.

Rules:

- Stack parts along Z using named height constants, so the overall height comes out exactly to the listing value.
- Put profile peaks exactly on the listed radius, and use a vertex count that's a multiple of 4. That makes the X and Y extents equal the diameter exactly.
- Don't add Bevel modifiers to parts whose size has to be exact. On the Glosola cap, a 0.05 cm bevel lowered the narrow rim around the recessed solar panel and cut 0.011 cm off the overall height. Making the recess deeper made it worse. Check sizes on the evaluated mesh, not just on the raw vertices.

## 3D printing exports

- Use the user's installed **3D Print Toolbox** extension (`bl_ext.blender_org.print3d_toolbox`) through `scripts/export_print3d.py -- <object> <out_dir> [OBJ|STL|PLY]`. Run Blender **without** `--factory-startup`, because that flag skips user extensions.
- The toolbox exports what Blender stores (meters) unless "Scene Scale" is on, and then it multiplies by `unit_settings.scale_length`. Slicers read mm, so the script sets scale_length to 1000 for the export session only. Check the result by reading the OBJ's vertex extents.
- Toolbox checks use Blender units. "Thickness" defaults to 0.001 (1 mm in this scene), which is fine. "Zero Faces/Edges" uses one 0.0001 limit for both area and length, so it over-reports in a meter scene. Report degenerate counts in mm yourself.
- Before exporting: put the part at the origin in print orientation and split its faces into triangles. In the build, dissolve degenerate geometry under 0.001 mm after any EXACT boolean union.
- The toolbox's OBJ export uses Blender's OBJ defaults: Y-up, with file (X, Y, Z) = Blender (x, z, −y), and it has no axis option. Z-up slicers then show the part on its side, as the user saw. Fix: after the checks, rotate the object +90° about X just before the toolbox export, and confirm the OBJ's Z extent equals the part height. STL and PLY are already Z-up.

## Blender 4.2 API notes

- Principled BSDF input names: `"Transmission Weight"`, `"Emission Color"`, `"Emission Strength"`. The pre-4.0 names `"Transmission"` and `"Emission"` raise `KeyError`.
- Also set `mat.diffuse_color` so materials show their color in Workbench and Solid viewport shading.
- `bmesh.ops.create_cone` takes `radius1`, `radius2` and `depth`, not `diameter1` or `diameter2`.
- Call `bmesh.ops.recalc_face_normals` after building faces by hand with `bm.faces.new`.
- `obj.dimensions` includes modifiers. Read it after linking the object, and divide by `CM` to report in cm.

## Preview renders

```sh
"$BLENDER" -b models/<NAME>.blend --factory-startup \
  -P ${CLAUDE_SKILL_DIR}/scripts/render_preview.py -- models/previews
```

This writes `<NAME>_front.png` (near eye level) and `<NAME>_top.png` (elevated, so the top surface shows). Both are framed to fit all mesh objects automatically. It uses the Workbench engine, which renders reliably headless, and doesn't modify the `.blend`. Clear materials render as opaque light gray in Workbench, which is expected.

## Fit-check renders (multi-part models)

```sh
"$BLENDER" -b models/<NAME>.blend --factory-startup \
  -P ${CLAUDE_SKILL_DIR}/scripts/render_fit_check.py -- models/previews
```

This writes two images, each object in its own flat color:

- `<NAME>_exploded.png`: the child parts pulled down below their parent.
- `<NAME>_section.png`: every mesh cut in half at Y = 0, framed on the parts.

It also prints the non-manifold edge count for each object. The section cut uses an EXACT Boolean with `use_self` and `use_hole_tolerant` turned on. Without them the cut silently doesn't happen on bodies built from overlapping shells.
